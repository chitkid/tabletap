# M5 Admin Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An admin runs the restaurant from `/admin`: the menu and its photographs, the tables and their printed QR codes (revocable), and a day's figures — while the guest and kitchen surfaces keep working exactly as they do now.

**Architecture:** Writes reuse the existing resources (`/api/menu/*`, `/api/tables/*`) behind the RBAC matrix rather than a parallel `/api/admin` tree. Photographs never pass through the API: it mints a presigned `PUT` with a server-chosen key and a size ceiling, the browser uploads straight to S3-compatible storage, and a confirmation call writes `image_url` only after the API has seen the object. A table carries a `qr_version` that travels inside the signed QR token and is compared when a guest claims, so reissuing a code invalidates every printed one at once. The dashboard is SQL, not a library.

**Tech Stack:** as M4 (pnpm 11, Turborepo 2, TypeScript 5.9, Fastify 5, Zod 4, Drizzle 0.45 + PGlite tests, better-auth 1.7, Socket.io 4.8, Stripe 22, Next.js 16, React 19, Tailwind 4, shadcn, Vitest 4, Playwright 1.62, Lighthouse 13) plus `@aws-sdk/client-s3` and `@aws-sdk/s3-request-presigner` (API), `pdfkit` + `@types/pdfkit` (API), `qrcode` (already in web; add to the API for the PDF), and MinIO as a Compose service.

**Spec:** `docs/superpowers/specs/2026-09-04-m5-admin-design.md` — read it before any task. Earlier specs and `docs/backlog.md` carry the rest.

- Work in a git worktree on branch `feat/m5-admin` created from `main` (`superpowers:using-git-worktrees`; worktree root under `.claude/worktrees/`). Paths below are relative to the worktree root. - TypeScript strict, `noUncheckedIndexedAccess`, `verbatimModuleSyntax` (`import type`); no `any`.
- TDD (red → verify → green → commit) for every behaviour change. Exempt: migrations, config schema lines, presentational markup, Dockerfiles and Compose, ADRs.
- **Every admin route is guarded by the RBAC matrix** (`requireAction('menu.write' | 'tables.write' | 'dashboard.read')`), and a `waiter` or `kitchen` principal must be refused on each one — with a test. - The browser never receives a storage credential: only a presigned URL the server built, with the key, the content type and the size ceiling fixed server-side.
- Destructive admin actions refuse rather than cascade: a category with items and a table with orders answer 409 `IN_USE`.
- Error envelope `{ error: { code, message, details? } }` on every non-2xx; bodies, params and queries validated inside handlers with `validate()` from `apps/api/src/lib/errors.ts`.
- Tokens only in `apps/` and `packages/ui/src`; 44 px targets (`h-11`); every control labelled; notices in `role="status"`; brand voice (plain verbs, no exclamation marks) — exact strings per task.
- Public URLs added in M5: `/admin` and its sub-paths only.
